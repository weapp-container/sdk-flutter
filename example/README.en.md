# Flutter SDK consumer

[简体中文](README.md) · **English**

This app uses the sibling `../weapp_container` package through a path dependency and loads the example pack from `assets/portable-pack`. The public Flutter SDK is `0.1.0-preview.7.1`, still a prerelease. See the [SDK README](../README.en.md) for pub.dev installation and target status, and the [public release status](https://github.com/weapp-container/weapp-container/blob/main/docs/public-sdk-release.en.md) for Apple native archive limitations.

## Run the Example

Run these commands from the `example/` directory:

```sh
# Generate the example pack, then add the platform project folders.
node shared/make-fixture.mjs --out assets/portable-pack
flutter create --empty --platforms=android,ios,macos,linux,windows .
flutter pub get
flutter analyze lib
flutter run -d <device-id>
```

`make-fixture.mjs` creates `assets/fixture-index.json` and the portable pack used by the app. The example's `.gitignore` excludes generated assets and platform folders, so repeat these generation steps before the first launch from the example directory. For a single target, replace `flutter create --platforms` with the platform you need.

After generating the Android project, replace `minSdk = flutter.minSdkVersion` with `minSdk = 26` inside `defaultConfig` in `android/app/build.gradle.kts`. This is the minimum supported version for `weapp_container_android`; projects generated by `tools/package.mjs` receive this value automatically.

The example covers the native View, taps and scrolling, navigation, messages, host methods, foreground state, failed reload, persistent reopen, and repeated close. Results appear on screen and in `sdk-flutter-report.json` inside the application-support directory.

To refresh the test pack and its `fixture-index.json` after changing the fixture, run this command again from `example/`:

```sh
node shared/make-fixture.mjs --out assets/portable-pack
```

The optional C ABI fixture check takes the runtime library, pack, and report path:

```sh
python3 shared/verify-fixture.py <shared-library> assets/portable-pack <report-path>
```

## Platform Builds

The repository workflow pins Flutter 3.47.7. Android builds require Android SDK 35 and 36, NDK `27.1.12297006`, and CMake 3.22.1. Build arm64 and x86_64 with:

```sh
flutter build apk --debug --target-platform android-arm64,android-x64
```

The minimum deployment targets are iOS 16 and macOS 12. In this prerelease, the standalone SDK archives referenced by the iOS/macOS Podspecs are unavailable. Prepare those native SDKs using the [source build guide](https://github.com/weapp-container/weapp-container/blob/main/docs/sdk-source-build.en.md). Linux and Windows use the Desktop CMake archives and require their target-system toolchains. Build, simulator, and device acceptance are recorded separately for each target.

## Source Locations

The Flutter example is in this repository's `example/` directory. The shared fixture generator is in `example/shared/`. The native Desktop consumer and its automation are in `native_desktop/`.
